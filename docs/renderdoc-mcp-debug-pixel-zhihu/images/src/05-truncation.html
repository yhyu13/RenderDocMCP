capped 版丢掉了什么：三层截断

debug_pixel 的返回经过三道闸门——每道都在扩展侧打包层，不在 RenderDoc
闸门 1 · 步数
默认走 64 步，硬顶 256。真实 PS 轨迹量级 1 万–1.5 万步，走不到头。
闸门 2 · 状态数
走到的状态里只返回最后 8 个（硬顶 32），前面的全扔。
闸门 3 · 值
留下的状态只有变量名；数值只在终点捞最多 24 个。中途谁变成什么，全部丢失。
本文真例（12 步小 shader）：capped 返回 12 步里的最后 8 步、0 个变量值；count:12, returned:8。轨迹越小，闸门 1、2 越无害——闸门 3 才是永远在流血的口子。
不是 RenderDoc 不给——扩展侧本来就拿到了完整状态流，是打包成 JSON 时把值扔了。
