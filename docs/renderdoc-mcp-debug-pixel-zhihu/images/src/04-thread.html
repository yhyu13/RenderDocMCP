脉络：从一个绿像素到一条轨迹文件

每一步回答一个问题；最后一刀是把状态流切到文件这一侧

需求 · 什么问题

画面上一个像素错了。谁写的？哪条指令算错的？

→

接缝 · 从哪下刀

pixel history 给出最后 passing fragment：event 184。它就是调试入口。

→

树根 · 数据从哪来

DebugPixel(x,y) 建调试器，ContinueDebug 循环吐出状态流。

主干 · 卡在哪

状态流在打包层被砍三层：步数、状态数、值。RenderDoc 本身给得出全量。

→

切开 · 刀口选哪

在"状态流"和"JSON 响应"之间插文件接缝：全量落盘，响应只回路径。

→

验证 · 怎么信

生产捕获实跑：12 步全值落盘，与像素历史逐位对上。

三个兄弟入口同一套根：DebugPixelDebugVertexDebugThread（compute）+ 新枝 debug_trace_export（pixel）
这一刀不是给 RenderDoc 加功能——是把它本来就给的数据，换一种方式递出来。
